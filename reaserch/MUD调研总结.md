# MUD 作为 Agent 生活环境的调研总结

调研日期：2026 年 11 月 17 日  
项目决定：停止继续跟进 MUD 路线，保留调研结果供参考。

## 1. 我们的目标与工作边界

我们的目标是复用一个已经成熟、能够持续游玩的生活化世界，让自己的 Agent 在其中生存、行动和交互。

世界应当已经具备地图、居民、设施、生活活动和运行规则。例如，角色能够通过已有机制工作、消费、居住、交流，并使用学校、银行等设施或服务。重点是这些活动已经有可执行的机制和实际后果，而不只是地点名称或文字描述。

我们主要负责：

- 将环境状态转换成 Agent 可以理解的观测。
- 将已有游戏动作封装成 AgentTools。
- 接入角色控制、会话、持续运行和日志记录。
- 做少量必要的接口与运行配置修改。

我们不承担：

- 从零创建城市、地图、NPC 和任务。
- 补建工作、教育、银行、经济等核心生活系统。
- 为使游戏可用而进行大规模移植、修复或历史存档恢复。
- 研究和重新设计原游戏自身的模拟机制。

文字、二维、三维都可以。表现形式不是核心筛选条件，完整世界能否复用才是。

## 2. MUD 的发展历程

MUD 是早期多人在线虚拟世界的重要形式。它曾在校园网络、计算机爱好者圈及商业在线服务中流行，后来逐渐退出大众游戏市场，但仍有持续运营的小众社区。

| 阶段 | 主要发展 |
| --- | --- |
| 1978—1980 年：诞生 | Roy Trubshaw 和 Richard Bartle 在英国 Essex 大学创造 MUD，实现多人同时进入一个文字世界，移动、探索和交流。 |
| 1980 年代：传播与商业化 | 从大学网络与拨号连接扩展到商业在线服务；MUD1 后以 British Legends 的名称运营。 |
| 1980 年代末—1990 年代：分支发展 | 出现战斗成长、社会交往、角色扮演和共同创作等路线，形成 LPMUD、DikuMUD、MUSH、MOO 等不同体系。 |
| 1990 年代中后期：商业与中文圈发展 | GemStone 等商业文字世界发展；中文圈形成侠客行及其分支，北大侠客行从 1996 年开始运营。 |
| 1990 年代末至今：图形化转向、小众延续 | 图形在线世界吸引更广泛受众；部分 MUD 保留稳定社区并持续更新，但已较少出现在大众游戏视野中。 |

当年的“流行”应放在早期联网用户规模较小的背景下理解，不能直接类比今天的大众游戏规模。也未找到统一、可比的行业数据来确定 MUD 的全球玩家峰值或当前热度排名。

图形化转向发生在 1990 年代末，早于 2005 年推出的 Unity。Unity 是后来降低图形世界开发门槛的工具之一，不是 MUD 最初失去主流地位的原因。

对这一转变的分析是：图形世界逐渐提供了多人身份、交易、组织和社会关系等体验，同时用画面、动作和空间降低了新玩家理解环境的成本；玩家聚集、商业投入和开发工具又进一步强化了这种转向。MUD 的许多设计被后来的在线游戏继承。

历史来源：[MUD 创作者的早期记录](https://mud.co.uk/richard/mudhist.htm)、[版本历史](https://mud.co.uk/richard/incarns.htm)、[Bartle 的历史研究](https://mud.co.uk/richard/International%20Handbook%20of%20Internet%20Research.pdf)、[GemStone 历史](https://gswiki.play.net/GemStone_history)、[北大侠客行官方百科](https://wiki.pkuxkx.net/)、[Unity 官方历史说明](https://unity.com/news/unity-technologies-celebrates-six-years-continual-leadership-and-innovation)。

## 3. MUD 的优势、缺点与独特性

### 3.1 优势

| 优势 | 对 Agent 环境的价值 |
| --- | --- |
| 命令与文本交互直接 | 可以从发送命令、接收消息开始封装工具，接入路径较直观。 |
| 通常无需图形渲染 | 环境开销可能较低，适合部署多个角色；实际总成本仍取决于游戏、接口和模型调用。 |
| 多人共享与持久运行 | 多个角色可以共享资源和事件，行为影响其他角色及后续世界状态。 |
| 服务端维护规则和状态 | 行动可以对应位置、物品、资金和权限变化，便于判断是否真正完成事情。 |
| 部分世界积累多年内容 | 可以复用已有职业、住房、商店、制造和贸易设计。 |
| 文本扩展成本较低 | 调整描述或增加文本观测通常不需要配套制作美术、建模和动画。 |

### 3.2 缺点

- **成熟线上世界不一定可完整获得。** 公开的可能只是引擎、客户端或核心库，地点、NPC、任务和世界数据库没有一起提供。
- **题材经常不匹配。** 大量完整 MUD 以战斗、升级、武侠和冒险为中心，生活系统只是辅助。
- **线上社会可能依赖真人玩家。** 长期形成的城市治理、商店和贸易生态，不会因复制服务端自动出现。
- **文字接口也有工程成本。** 异步消息、文本解析、命令歧义、编码和状态提取仍需处理。
- **历史项目可能带来维护负担。** 驱动兼容、缺失文件、残缺存档或未完成流程，可能使适配变成修复。
- **角色扮演描述不一定改变状态。** “正在上课”或“正在工作”的文字，未必对应课程、成绩、工资或库存机制。
- **表现和展示相对受限。** 对人类观察者而言，图形化空间、动作和外观通常更直观；文字的低渲染成本不代表整体使用成本更低。

### 3.3 是否存在独一无二的特点

对本项目而言，没有一项关键能力只能通过 MUD 获得。多人在线、持久状态、经济系统、角色扮演和结构化动作，其他类型游戏同样可以提供。

MUD 的鲜明特点是：用较少的表现资源，通过文字、命令和可编程对象，承载复杂的多人交互。文字也允许描述没有专门动画的行为和细腻社会情境。

但自由描述需要与规则执行区分。我们需要的是已有规则能够支持 Agent 持续行动，而不仅是语言表达自由。因此，这些特点不足以弥补世界内容、题材和交付状态的不匹配。

## 4. 项目筛选标准与证据边界

本次按以下条件筛选：

1. 有可复用的完整游戏内容，而不只是空框架。
2. 能自行运行服务端，或有明确可获得的完整环境。
3. 已有足够的生活、生产或经济活动，不要求游戏完全没有战斗。
4. 主要工作能够限定在正常安装配置和 Agent 适配范围。
5. 不依赖我们补建核心内容、恢复世界或长期维护原项目。

**本轮结论来自官方说明、公开源码、部署文件，以及恢复者的测试记录；没有由我们实际启动这些游戏、完成普通角色的完整游玩与长期运行验收。**

以下三件事不能混淆：

- “能够连接在线服”不等于“完整世界能够下载自建”。
- “有公开代码和可运行说明”不等于“已经通过我们的部署验收”。
- “恢复者验证过某个功能”不等于“普通新角色能够自然走通全部生活流程”。

| --- | --- | --- | --- |

| **重生的世界：不同历史快照** | 城市、政府、房地产、生产和企业等代码；部分版本已有恢复者的生产闭环测试。 | 版本差异大；部分快照经济不可达，另一些测试依赖管理员初始化城市或调用内部接口。 | 内容方向接近，交付状态不足，不符合不补建、不救旧项目的要求。 |
| **炎黄群侠传** | 完整武侠地图、门派、技能、装备、成长和任务，有本地部署说明。 | 生活活动不是主要玩法，武侠战斗成长是核心。 | 题材不匹配。 |
| **tbaMUD** | 服务端随附世界区域、NPC、物品、商店和战斗等内容。 | 主要是传统奇幻 RPG，未核实到足以满足需求的生活城市内容。 | 内容比空框架完整，但生活目标不匹配。 |

### 5.1 AwakeMUD CE：最重要的补充发现

公开源码与数据可以确认：

- 银行支持存款、取款、查询和向离线角色转账。
- 具体公寓随公开库提供，已有房东、租赁、交租、欠租通知、到期驱逐和物品保存机制。
- 已有出租车，以及车辆和无人机维修。
- 随库包含快递等非战斗任务，由 NPC 和任务系统派发、结算，不需要真人 GM 临时编写。
- 默认构建可以使用公开世界；线上额外私有区域不是默认运行前提。

长期实验需要正确选择部署模式：默认本地开发模式下，部分住房保存逻辑会跳过。这属于运行配置，但我们尚未验证正常运行模式下的完整闭环。

来源：[官方仓库与部署说明](https://github.com/luciensadi/AwakeMUD)、[功能帮助](https://awakemud.com/dokuwiki/doku.php?id=helpfiles)、[公开公寓数据](https://raw.githubusercontent.com/luciensadi/AwakeMUD/master/lib/housing/12400/1A/apartment_info.json)、[任务数据](https://raw.githubusercontent.com/luciensadi/AwakeMUD/master/lib/world/qst/392.qst)、[构建与部署配置](https://raw.githubusercontent.com/luciensadi/AwakeMUD/master/src/Makefile)。

### 5.2 模拟华附：校园生活内容确实存在

源码和恢复者记录支持读书、自习、看单车领工资、麦当劳洗盘领工资、钓鱼、扫楼梯及寻物任务等活动。餐厅也有食物、价格、供应和营业时间处理。

但它仍含战斗工作与恶搞元素，不能称为完全没有战斗或奇幻内容的教育模拟；也没有充分证据支持完整课程、考试、成绩和升学系统。恢复者部分测试通过管理员传送直达场景，证明功能存在，但未证明完整普通玩家流程已就绪。

来源：[游戏与恢复说明](https://mudlibs.fluffos.info/mnhf/)、[工作帮助](https://raw.githubusercontent.com/fluffos/mudlibs/main/libs/mnhf/work/doc/help/hfjobs.txt)、[自习代码](https://raw.githubusercontent.com/fluffos/mudlibs/main/libs/mnhf/work/d/huafu/libzixi.lpc)、[餐厅代码](https://raw.githubusercontent.com/fluffos/mudlibs/main/libs/mnhf/work/d/huafu/mdc.lpc)、[恢复测试记录](https://raw.githubusercontent.com/fluffos/mudlibs/main/libs/mnhf/NOTES.md)。历史收藏的整体许可不能自动视为每款游戏的许可，参见[来源与许可说明](https://github.com/fluffos/mudlibs#provenance-and-licensing)。

### 5.3 Federation 2：基础世界与容器方案均有依据

原作者提供 Sol 基础世界文件；F2RE 的容器构建文件会编译服务端、拉取地图并安装基础数据。这比只有引擎或零散源码更接近可复用环境，但它是第三方研究分支，不能直接套用当前社区服的稳定性和内容范围。

来源：[原作者官网](https://www.ibgames.com/)、[Sol 文件下载](https://www.ibgames.com/fed2/workbench/sol/index.html)、[F2RE](https://github.com/SCUPPERfoundation/f2re)、[容器文件](https://github.com/SCUPPERfoundation/f2re/blob/main/Containerfile.fedora)、[地图仓库](https://github.com/SCUPPERfoundation/fed2-maps)。

### 5.4 重生的世界：结论必须限定版本

- `revivalworld` 快照的恢复说明指出，普通新角色无法正常启动随附废弃城市的经济链。
- 另一份 `zsdsj` 快照已有买地、建造、种植、收成和企业创建测试，但场地初始化、入籍或分区等步骤仍使用管理员操作。

因此，不能说所有版本的经济系统都不可用，也不能说已经交付了普通角色可以直接生活的完整城市。

来源：[revivalworld 快照说明](https://mudlibs.fluffos.info/revivalworld/)、[zsdsj 快照与测试记录](https://mudlibs.fluffos.info/zsdsj/)。

其他候选来源：[EmpireMUD 官网](https://empiremud.net/)、[新服配置指南](https://github.com/EmpireMUD/EmpireMUD-2.0-Beta/blob/beta-dev/doc/getting-started.txt)、[炎黄群侠传](https://github.com/oiuv/mud)、[tbaMUD](https://github.com/tbamud/tbamud)。

## 6. 内容丰富，但不能直接视为可自建环境的 MUD

| 项目 | 现有丰富内容 | 完整复用的限制 |
| --- | --- | --- |
| **Discworld MUD** | 银行、工资、住房、商店、公会和非战斗工作。 | 官方明确公开 mudlib 不包含完整线上地点、NPC 和物品。 |
| **Achaea** | 玩家城市、政府职位、贸易、制造和社会组织。 | 未查到官方完整世界自托管发行，部分城市生态依赖玩家。 |
| **GemStone IV** | 长期积累的奇幻世界、角色成长、故事与运营活动。 | 主要作为在线服务运营，未核实官方完整自托管发行。 |
| **Aardwolf** | 大量区域、任务、探索、氏族和成长内容。 | 官方客户端下载不等于服务端与世界下载；战斗成长占重要位置。 |
| **Sindome** | 城市职业、企业、公寓和社会关系。 | 未找到官方完整世界可自建发行；强角色扮演与冲突题材也不同于一般生活模拟。 |
| **北大侠客行** | 长期积累的武侠世界、门派、任务和玩家社区。 | 个人公开历史库不能保证等同当前官方世界，题材也偏武侠成长。 |

这些作品可以证明成熟文字世界存在，但不能据此认定我们能够完整拿来部署。若走运营方合作路线，还需另外确认环境交付与 Agent 接入条件。

## 7. 最终决定

在本次检索和核实范围内，仍未确认一个同时满足以下条件的项目：

- 已有足够丰富、可持续的生活化城镇内容。
- 完整环境可以自行部署。
- 普通角色能够自然进入并完成生活活动。
- 后续工作主要是 Agent 适配，而非补建、恢复或维护原游戏。

**最终决定：本项目不再继续跟进 MUD 路线，也不投入后续环境开发与适配。** 调研结果保留归档，其他类型的成熟环境另行讨论。

这一决定基于当前候选与项目目标的匹配度及预期工程边界，不是否定 MUD 的内容价值，也不是对所有 MUD 作穷尽性判断。

## 8. 可直接用于汇报的结论

> 我们希望直接复用成熟的生活化世界，主要开展 Agent 接入与适配，不承担游戏内容和核心机制开发。MUD 具有文本交互直接、运行开销较低、多人持久世界和可编程性等优势，也确有内容丰富的长期运营作品。现有候选仍存在题材偏差、完整世界交付不足、长期生活闭环未验证或维护成本不明等问题，尚未确认能够把工作限制在少量适配范围内。结合项目定位，我们决定不再继续跟进 MUD 路线，保留调研结果，转而另行评估其他成熟环境。
